    26. Dal dizionario a XML e viceversa

    In questa sede ci proponiamo di scoprire il modulo [xml2dict] che permette di trasformare:

    • una stringa XML in un dizionario:
    • un dizionario in una stringa XML;

    Prima dell’avvento del jSON, la risposta dei servizi web era spesso in formato XML (eXtended Markup Language). Inoltre, il protocollo di questi servizi web era spesso SOAP (Simple Object Process Protocol). SOAP è un protocollo basato sul protocollo web HTTP. Attualmente (2020), i servizi web sono prevalentemente di tipo REST (Representational State Transfer). I servizi web che abbiamo studiato non rientrano in nessuna di queste categorie, ma sono decisamente più vicini al REST che al SOAP. Tuttavia, preferisco definirli di tipo «libero» o «sconosciuto», poiché non rispettano tutte le regole del REST.

    Mostreremo quanto sia facile trasformare le nostre architetture client/server jSON in architetture client/server XML. È sufficiente utilizzare il modulo [xmltodict].

def transform(message: str, dictionary: dict):
    # log
    print(f"\n{message}-------")
    print(f"dictionnaire={dictionary}")
    # dizionario -> xml
    xml1 = xmltodict.unparse(dictionary)
    print(f"xml={xml1}")
    # xml -> OrderedDict
    ordereddict_dictionary1 = xmltodict.parse(xml1)
    print(f"ordereddict_dictionary1={ordereddict_dictionary1}")
    # OrderedDict -> dizionario
    print(f"dict_dictionary1={ordereddict2dict(ordereddict_dictionary1)}")

    • le righe 23 e 27 evidenziano un punto importante:
      • riga 23: i valori associati alle chiavi del dizionario [result] sono numeri;
      • riga 26: i valori associati alle chiavi del dizionario [ordereddict_dictionary1] sono stringhe di caratteri. Si tratta di un punto debole della libreria [xmltodict]. Il suo metodo [parse] produce solo stringhe di caratteri. Ciò è facilmente comprensibile:
        • riga 25: la stringa XML da cui viene generato il dizionario. In questa stringa non vi è alcuna indicazione del tipo di dati incapsulati nei tag XML. [xmltodict.parse] agisce nel modo più logico: lascia tutto come stringa di caratteri nel dizionario generato. Esistono altre librerie simili a [xmltodict] in cui il tipo dei dati incapsulati è indicato nei tag. Si potrebbe trovare, ad esempio, il tag [<enfants type=’int’>2</enfants>];
        • la conseguenza di ciò è che quando si utilizza un dizionario generato dal modulo [xmltodict] è necessario conoscere il tipo dei dati che incapsula per poter passare dal tipo ‘str’ al tipo reale del dato;

    Soffermiamoci ora sul metodo [ordereddict2dict] che trasforma un tipo [OrderedDict] in un tipo [dict]:

    
# xmltodict.parse per passare da XML al dizionario. Il dizionario deve avere una radice
# il dizionario generato è di tipo OrderedDict
# xmltodict.unparse per passare dal dizionario a XML

def check(value):
    # se il valore è di tipo OrderedDict, lo si trasforma
    if isinstance(value, OrderedDict):
        value2 = ordereddict2dict(value)
    # se il valore è di tipo lista, lo si trasforma
    elif isinstance(value, list):
        value2 = list2list(value)
    else:
        # si tratta di un tipo semplice, non di una collezione
        value2 = value
    # si restituisce il nuovo valore
    return value2


def list2list(liste: list) -> list:
    # la nuova lista
    newliste = []
    # si utilizzano gli elementi della lista parametro
    for value in liste:
        # si aggiunge value alla nuova lista
        newliste.append(check(value))
    # si restituisce la nuova lista
    return newliste


def ordereddict2dict(ordered_dictionary: OrderedDict) -> dict:
    # OrderedDict -> dizionario in modo ricorsivo
    newdict = {}
    for key, value in ordered_dictionary.items():
        # si memorizza il valore nel nuovo dizionario
        newdict[key] = check(value)
    # si restituisce il dizionario
    return newdict
    • riga 30: la funzione [ordereddict2dict] riceve come parametro un tipo [OrderedDict];
    • riga 32: il dizionario di tipo [dict] che verrà restituito alla riga 37 dalla funzione;
    • riga 33: vengono esaminate tutte le tuple (chiave, valore) del dizionario [ordered_dictionary];
    • riga 35: nel nuovo dizionario, la chiave [key] viene mantenuta, ma il valore associato non è [value] bensì [check(value)]. La funzione [check(value)] ha il compito di individuare, se [value] è una collezione, tutti gli elementi di tipo [OrderedDict] e di trasformarli nel tipo [dict];

    Il metodo [check] è definito alle righe 5-16:

    • riga 5: non si conosce il tipo di [value], quindi non è stato possibile scrivere [value : type];
    • righe 7-8: se [value] è di tipo [OrderedDict], allora si chiama in modo ricorsivo la funzione [ordereddict2dict] che è stata appena commentata;
    • righe 9-11: un altro caso possibile è che [value] sia una lista. In questo caso, alla riga 11, si chiama la funzione [list2list] delle righe 19-27;
    • righe 12-14: l'ultimo caso è quello in cui [value] non è una collezione, ma un tipo semplice. La funzione [check], così come le funzioni [ordereddict2dict] e [list2list], è ricorsiva. È noto che in tal caso occorre sempre prevedere il caso in cui la ricorsione si interrompa. Le righe 12-14 rappresentano proprio questo caso;
    • riga 16: la funzione [check], chiamata in modo ricorsivo o meno, produce un valore [valeur2] che deve sostituire il parametro [value] della riga 5;

    Il metodo [list2list], definito alle righe 19-27, utilizza una lista passata come parametro. Esplorerà tale lista e sostituirà ogni valore di tipo [OrderedDict] in essa contenuto con un valore di tipo [dict].

    • riga 21: il nuovo elenco che verrà creato dalla funzione;
    • righe 23-25: tutti i valori [value] dell’elenco vengono esaminati e sostituiti con il valore [check(value)]. Questo valore [value] può a sua volta contenere elementi di tipo [list] o [OrderedDict]. Essi saranno trattati correttamente dalla funzione ricorsiva [check];
